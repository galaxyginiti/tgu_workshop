# Прогнозирование оттока абонентов «СвязьРегион»

Команда: Анишко Руслан, Шоймардонов Ботир, Адылбаев Камал. Дата сдачи: 14 ноября 2026.

## Задача в двух предложениях

Уходящим считаем абонента, расторгнувшего договор в календарном месяце, который начинается на дату расчёта T (первое число месяца, 00:00 МСК). На эту дату ранжируем всех активных абонентов по риску и формируем для удерживающей кампании список не более чем из 10% активной базы.

## Как запустить

- **Входы:** `solution/stage4_features/output/` (`features.csv`, `labels.csv`, `split.csv`) и сохранённая модель `solution/stage5_models/output/model/candidate.joblib`.
- **Начало расчёта:** подготовленные признаки этапа 4. Пересобирать исходные данные не нужно, но полная цепочка от исходников тоже есть.
- **Среда:** Python 3.14.6 (нужен 3.11+), версии библиотек — в `solution/requirements.txt`. Сохранённая модель рассчитана на эти же версии.
- **Выходы:** `solution/stage6_final/output/`: `quality_table.csv` (метрики), `test_candidate_list.csv` и `test_baseline_list.csv` (списки контактов), `checks_stage6.csv` (проверки).

Запуск из корня репозитория:

```bash
python solution/run_all.py --stage 6
```

На Linux и macOS вторая команда: `source .venv/bin/activate`. Другие варианты запуска:


Первая команда — вся цепочка от исходных файлов до итоговых таблиц, вторая — загрузка модели и сверка с прогнозами validation без обучения.

**Что означает список контактов.** Файл содержит `customer_id` и `snapshot_at` (ключи), `score` — оценку риска, `rank` — место в общем списке, `selected` — попадание в K. Будущая метка в списке не хранится: она нужна только для оценки, при реальном прогнозе она неизвестна.

## Результаты

| Период | Подход | N / K | Найдено / ушли | Recall@K | Precision@K |
|---|---|---|---|---:|---:|
| Validation | Baseline | 1 929 / 192 | 14 / 63 | 22,2% | 7,3% |
| Validation | Модель | 1 929 / 192 | 19 / 63 | 30,2% | 9,9% |
| Test | Baseline | 1 916 / 191 | 30 / 65 | 46,2% | 15,7% |
| Test | Модель | 1 916 / 191 | 29 / 65 | 44,6% | 15,2% |

Преимущество модели на validation (+5 уходов) на test не сохранилось: при одном лимите в 191 контакт она нашла на 1 уход меньше правила по долгу. Recall@K обоих подходов сильно меняется от месяца к месяцу (у правила 22,2% в августе и 46,2% в сентябре), и один test-месяц не доказывает устойчивость на будущих периодах.

## Небольшой анализ

**Одно сравнение сегментов** (T = 01.09.2026, отбор из общего top-K, `segment_debt_test.csv`):

| Группа | N | Ушли | Отток | Модель: выбрано / найдено | Правило: выбрано / найдено |
|---|---:|---:|---:|---|---|
| Долг > 0 | 426 | 40 | 9,4% | 191 / 29 | 191 / 30 |
| Долг = 0 | 1 490 | 25 | 1,7% | 0 / 0 | 0 / 0 |

Оба списка целиком состоят из должников, и в них 155 из 191 абонента общие. Поэтому модель фактически только переставляет должников, и результат близок к правилу: 27 уходов нашли оба подхода, 2 — только модель, 3 — только правило, 33 — никто. **25 из 65 уходов (38%) пришлись на абонентов без долга, и при этом лимите их не достаёт ни один из подходов.**

**Три признака** (`three_features.csv`):

| Признак | Что измеряет и почему может быть связан с уходом | Основание: EDA на train и коэффициенты |
|---|---|---|
| `debt_last_rub` | Долг на конец прошлого месяца. Неоплата может отражать снижение интереса к услуге или финансовые трудности | Долг > 0: 7,5% (276 из 3 661) оттока, долг = 0: 1,4% (164 из 12 035), направление на всех 8 датах T. Коэффициент +0,17 |
| `payment_delay_last_days` | Задержка оплаты в прошлом месяце. Систематическая задержка может предшествовать отказу от услуги | Задержка > 10 дней: 8,7% (243 из 2 793), без задержки: 1,4% (123 из 8 705). Коэффициент +0,36 |
| `traffic_last_gb` | Трафик в прошлом месяце; пропуск означает «неизвестно», а не ноль. Низкое использование может означать, что абонент уже пользуется услугами реже | Нижние 20% по трафику: 3,6% (111 из 3 113), остальные группы: 2,3–2,9%; связь слабая. Коэффициент −0,24 |

Коэффициенты взяты у логистической регрессии `exp04_lr_c01_balanced` (масштабированные признаки, `lr_coefficients.csv`), а не у выбранного бустинга: важность признаков для него не считалась. Связь в данных не доказывает причину ухода. Выводы EDA сами по себе не доказывают важность признака для обученной модели.

## Вывод и ограничения

**Результат.** На отложенном сентябре модель нашла 29 из 65 уходов, правило по долгу — 30, при одном лимите в 191 контакт. Модель не превзошла правило. Это согласуется с проверкой этапа 5: на 6 датах вне обучения (4 временных фолда, validation, test) правило нашло 141 из 364 уходов, а этот метод — 133.

**Рекомендация заказчику.** В ближайшей кампании отбирать абонентов простым правилом по долгу, модель пока не внедрять: она сложнее и не находит больше уходов. Правило находит примерно в 4,6 раза больше уходов, чем случайный выбор того же размера (46,2% против 10%), но это один месяц. Следующие шаги:

1. Провести ограниченный пилот с контрольной группой, чтобы измерить, сколько уходов предотвращает контакт.
2. Отдельно искать сигналы для абонентов без долга: на них пришлось 38% уходов на test.
3. Повторять сравнение модели и правила на новых месяцах.

**Два главных ограничения.**

1. Мало событий и один test-месяц: 65 уходов, разница в 1 уход находится в пределах случайности, а качество сильно меняется от месяца к месяцу.
2. Риск ухода не равен эффекту удерживающего контакта: неизвестно, сколько уходов предотвратит предложение. Денежный эффект без исходных данных не оценивался.

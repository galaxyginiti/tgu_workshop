# Отчёт об обучении моделей (этап 5)

Команда: Анишко Руслан, Шоймардонов Ботир, Адылбаев Камал. Версия репозитория: тег `stage-5`. Дата запуска: 06.11.2026.

**Итог в трёх строках.** По заранее заданному правилу выбран градиентный бустинг `exp05_hgb_leaf7`: на validation он нашёл 19 уходов из 63 против 14 у правила по долгу при одном K = 192. Это преимущество не доказано: на четырёх временных фолдах внутри train тот же метод нашёл меньше правила (85 против 97 из 236), а разрыв train/validation большой. Правило по долгу остаётся рабочей альтернативой, сравнение решит однократная проверка на test на этапе 6.

**Проверка входа.** `features`, `labels`, `split` соединяются только по `(customer_id, snapshot_at)`, позиционного присваивания нет. Ключи уникальны, множества совпадают, строки не потеряны, число строк на каждой T равно независимому расчёту по журналу событий. Горизонты train заканчиваются не позже начала validation.

**Сверка с презентацией 5.** N = 1 929, K = 192 и 63 ушедших совпадают с примером преподавателя на validation, то есть база и метка построены согласованно.

## Baseline и кандидаты

**Baseline.** Сортировка по `debt_last_rub` (долг на конец M−1) по убыванию, при равенстве — `customer_id` по возрастанию. Неизвестный долг ставится после известных и нулём не считается. Train-результат совпадает с таблицей этапа 4 по K и найденным на всех 8 датах.

**План** зафиксирован до обучения отдельным коммитом `deff085` (`solution/config/experiments.json`): шесть конфигураций и правило выбора.

| ID | Метод | Что проверяем |
|---|---|---|
| `exp01_lr_c001` | Логистическая регрессия, C = 0,01 | Сильная регуляризация: долг, задержка и оплата коррелируют |
| `exp02_lr_c01` | Логистическая регрессия, C = 0,1 | Средняя регуляризация |
| `exp03_lr_c1` | Логистическая регрессия, C = 1 | Слабая регуляризация |
| `exp04_lr_c01_balanced` | Логистическая регрессия, C = 0,1, веса классов | Веса классов как отдельный опыт |
| `exp05_hgb_leaf7` | HistGradientBoosting, 7 листьев, 100 итераций, шаг 0,07 | Пороги и взаимодействия |
| `exp06_hgb_leaf15` | HistGradientBoosting, 15 листьев, 100 итераций, шаг 0,07 | Более сложные деревья: проверка на переобучение |

**Подготовка.** Для каждого опыта создаётся новый Pipeline, подготовка и модель обучаются только на train.

- Логистическая регрессия: медиана train + флаги пропуска, масштабирование, One-Hot (58 столбцов).
- Бустинг: числа как есть, пропуски обрабатывает само дерево, One-Hot для категорий (44 столбца).
- Новая категория на validation даёт нули в One-Hot (`handle_unknown="ignore"`).
- Early stopping отключён: встроенная внутренняя подвыборка случайна по строкам и нарушила бы порядок времени.

**Отличие от плана этапа 4.** Там параметры предполагалось выбирать на фолдах. В задании этапа 5 выбор сделан по validation, поэтому фолды остались только проверкой устойчивости и в выборе не участвуют.

## Результаты

Журнал: [Журнал_экспериментов.md](Журнал_экспериментов.md). Таблица по каждой T с N, K, ушедшими, найденными и метриками: `output/metrics_by_T.csv`. Train — macro по 8 датам; validation — одна дата, поэтому macro = pooled. AP — `average_precision_score`.

| Подход | Train Recall@K | Validation Recall@K | Validation найдено / ушли | Validation Precision@K | Validation AP |
|---|---:|---:|---|---:|---:|
| Baseline | 39,6% | 22,2% | 14 / 63 | 7,3% | 0,0583 |
| `exp01_lr_c001` | 41,2% | 25,4% | 16 / 63 | 8,3% | 0,0628 |
| `exp02_lr_c01` | 42,2% | 27,0% | 17 / 63 | 8,9% | 0,0616 |
| `exp03_lr_c1` | 42,2% | 27,0% | 17 / 63 | 8,9% | 0,0624 |
| `exp04_lr_c01_balanced` | 41,7% | 28,6% | 18 / 63 | 9,4% | 0,0630 |
| **`exp05_hgb_leaf7`** | **61,9%** | **30,2%** | **19 / 63** | **9,9%** | **0,0783** |
| `exp06_hgb_leaf15` | 83,0% | 30,2% | 19 / 63 | 9,9% | 0,0651 |

**Разрыв train/validation** (`output/train_validation_gap.csv`).

- У baseline нет обучаемых параметров, но Recall@K падает на 17,4 п.п. Значит, август сложнее прошлых месяцев сам по себе.
- У логистической регрессии разрыв 13–16 п.п. — такого же порядка, явного переобучения нет.
- У бустинга разрыв 31,7 и 52,9 п.п., AP на train 0,39 и 0,69 против 0,08 и 0,07 на validation. Это **переобучение**, и оно растёт со сложностью деревьев. Возможная причина (не проверялась): на train один абонент встречается до 8 раз, а точный стаж и постоянные поля помогают деревьям его запомнить.

**Почему август сложнее** (`output/debt_signal_by_T.csv`). Доля абонентов с долгом обычная: 22,8% против 22,5–25,2% на train. Но среди ушедших с долгом только 49,2% (31 из 63) против 54–69% на датах train. Отток абонентов без долга вырос до 2,1% против 1,1–1,6%. Правило по долгу таких уходов не видит. Одной датой причину не установить.

**Устойчивость** (`output/stability_summary.csv`). Весь Pipeline обучается заново на расширяющемся окне, оценка — на следующей дате. Найдено на 01.04–01.07.2026 из 236 уходов при одном K, и в сумме с validation — из 299:

| Подход | Фолды, найдено из 236 | Фолды, Recall@K | + validation, найдено из 299 |
|---|---:|---:|---:|
| Baseline | 97 | 41,1% | 111 |
| `exp01_lr_c001` | 95 | 40,3% | 111 |
| `exp02_lr_c01` | 93 | 39,4% | 110 |
| `exp03_lr_c1` | 91 | 38,6% | 108 |
| `exp04_lr_c01_balanced` | 90 | 38,1% | 108 |
| `exp05_hgb_leaf7` | 85 | 36,0% | 104 |
| `exp06_hgb_leaf15` | 75 | 31,8% | 94 |

Ни одна модель не обогнала правило по долгу на этих пяти датах. Чем сложнее модель, тем меньше она находит вне обучения. Оговорка: на фолдах модели обучены на 4–7 месяцах, а не на 8.

## Выбор

**Правило, заданное до сравнения:** максимальный Recall@K на validation; при равенстве — максимальный AP; при полном равенстве — первый в плане.

**Выбран `exp05_hgb_leaf7`.** Он и `exp06_hgb_leaf15` нашли по 19 уходов, равенство решил AP: 0,0783 против 0,0651.

**Разница с baseline:** +5 уходов (19 против 14), Recall@K +8,0 п.п. при одном K = 192. Найденные: 14 общих, 5 только модель, 0 только правило, 44 не нашёл никто (`output/validation_overlap_with_baseline.csv`). В обоих списках 159 из 192 абонентов одинаковые.

**Ограничения этого вывода.**

- Один месяц validation: при ~63 уходах стандартная ошибка Recall@K около 6 п.п., то есть примерно 3–4 ухода. Парный тест знаков (5 против 0) даёт p = 0,0625 — на границе случайности.
- По этому месяцу сравнивались шесть конфигураций, так что оценка победителя завышена и больше не является независимой.
- Фолды указывают в обратную сторону. Заранее заданное правило не меняем, но преимущество кандидата считаем **неподтверждённым**.

**Что будет, если baseline окажется лучше на test:** модель не объявляется готовой к внедрению, кампания работает по правилу долга. Это допустимый результат. Даже победа модели покажет только лучшее ранжирование риска, но не эффект удерживающего контакта.
